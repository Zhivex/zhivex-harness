# HAR-HU-14 and HAR-HU-20 — live baseline and daily CLI pilot

Date: 2026-09-20. Decision: **HOLD the 1.1 release recommendation**.

The authorized frozen cohort was executed once against each installed artifact using OpenAI `gpt-5.6-luna`. Baseline and candidate each solved 6/10 tasks independently; only 4/10 runs reached `completed`. No evaluation attempt was retried or used to tune the candidate. The predeclared release criterion required all ten candidate tasks to pass. Completing this measurement closes HU-14 and HU-20; it does not mean the product passed the release criterion.

The development result is retained unchanged; no extra development or evaluation provider attempt was run. The answer oracle was also constrained to durable assistant output before the first development call. Dataset prompts and success criteria were unchanged.

The user explicitly authorized the provider, isolated code payload and API costs after the initial automatic approval rejection. Exactly 2 development and 20 evaluation attempts were executed. Per-task bounds: 12 steps, 60,000 input tokens, 4,096 output tokens, 150 seconds. Runtime accounting is reported usage, not a guaranteed billing ceiling. Disposable workspaces were removed and original repository checkouts were not edited by the pilot.

## Prioritized observed friction and exit decision

1. **P1 — Governed edits do not reliably reach terminal completion.** All six repair/feature runs failed in both artifacts, including independently correct patches. Diagnose typed termination causes and budget/approval continuation boundaries before recommending daily use for edits. The sanitized report does not retain provider error payloads, so these results alone cannot attribute a root cause to the model, provider or runtime.
2. **P1 — Four candidate tasks remain independently incorrect.** H03, H04, S04 and S05 did not satisfy their predeclared oracle. Retain them as known failures; improvements must be assessed with a new held-out cohort, not reruns presented as fresh evidence.
3. **P2 — Approval policy friction.** Baseline had three denials and candidate two. The bounded operator approved only named target-file edits and the exact pilot check; other actions were rejected. Distinguish an operator-policy mismatch from a product defect before changing permissions.
4. **P2 — Usage and cost visibility.** Correctness was unchanged while candidate reported token usage increased. Monetary cost remains unknown without a dated price source; inspect route-level accounting before optimizing.
5. **P2 — Evaluation observability.** Preserve typed terminal reasons and allowlisted tool names in the next protocol to explain failures without retaining private tool payloads. This pilot deliberately records failed status and independent outcomes without claiming unobserved causes.

**HOLD** remains the release decision under the frozen policy. The pilot is an automated operator exercise in two real repository snapshots, not a human usability study, broad provider certification, competitive parity claim or statistical estimate. Local deterministic gates remain separately green: 610 tests, types/build/contracts/docs/migrations and installed package/PTY/first-use smoke.
