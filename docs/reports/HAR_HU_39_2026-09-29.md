# HAR-HU-39 — Desktop package boundary, ready for review

Local changes on `feat/provider-reliability-acceptance`; no new commit, push,
PR or publication. The existing HU43 changes remain in the same worktree.

## Initial inspection and migration plan (historical)

HU37's engine, protocol, client and service entrypoints exist in this checkout.
The ADR requires actual installed-package evidence, not renamed source imports.
Desktop still uses five internal source bridges, a build-time version substitution
and a SQLite `createRequire` rewrite. Its persistence bridge exposes low-level
SQLite ownership/file operations used by update/recovery. These cannot simply
be published as a stable general-purpose API.

Remaining migration:

1. Consume the installed Harness dependency for model metadata and the existing
   engine/protocol/service APIs. Declare the compatible package version explicitly.
2. Replace persistence internals with a reviewed host-only state contract or
   narrowly versioned integration entrypoint preserving leases and recovery.
3. Remove repository-source assumptions from Desktop build/package scripts.
4. Verify the packaged app's conversation, approval, restart and diff behavior
   using the installed candidate. Existing HU43 fixture smoke is not this evidence.

## State contract increment

`src/persistence/host-database-backup.ts`, preserving its SQL, checks, private
permissions, receipt/error behavior and cleanup. Desktop's former implementation

## Completed migration and packaged acceptance

All Desktop application imports now use declared Harness package exports. The
architecture gate rejects repository source, package-root/deep imports and Code
dependencies. Host provider discovery uses `/desktop/v1/providers`; renderer
metadata uses `/models`. State operations remain narrowly versioned and do not
expose arbitrary SQL.

`bun run prepare:desktop` builds and packs Harness, installs those exact bytes in
an isolated consumer and prepares Desktop's dependency. Build and packaging
verify its version, resolved installation and SHA-256; they reject source links,
modified artifacts and inconsistent build metadata. Desktop bundles the installed
package without version substitution or SQLite source rewriting. CI prepares
this installed dependency before Desktop tests.

The compatible dependency is pinned to `1.3.0-rc.3` **plus the new required
entrypoints and candidate identity**, not every artifact with that version. The
published RC3 lacks these contracts and is rejected. A subsequent release must
assign and pin its own version; broader compatibility belongs to HU40.
