# HAR-HU-25 — CLI connected to the local service

Implemented opt-in service mode for run/resume/chat and session list/inspect/rename.
Direct mode remains the default. Runtime configuration belongs to the host; the CLI
negotiates the shared contract, reads durable replay and submits revision-bound
commands. Result serialization is shared with the direct CLI and persisted in run
metadata for later clients. Host scope is explicit on admission.

Validation on 2026-09-20: 627 tests passed, 0 failed, 79 files; TypeScript runtime
and tooling, build, docs and public contract checks passed. The reviewed Stable
signature changes only add --service to the existing option-name union/definitions;
JSON/JSONL schemas and original command behaviors remain compatible.

The new regression streams 450 text chunks and verifies all replay pages, monotonic
JSONL sequences and schema-valid session list/inspect. Installed package smoke
executes the packaged CLI under Node: starts a pending edit, a separate client
inspects it, the service receives SIGKILL, dead-owner recovery rotates credentials,
the CLI resumes the same approval, and the file changes once with one completed
journal receipt. Stale decisions fail. No live provider request was used.

Limitations: explicit experimental service option; configuration and commands outside
the documented service matrix use direct mode. Old runs without the persisted CLI
projection remain inspectable but cannot manufacture a run-result document. Errors
require state reconciliation rather than blind mutation retries. No publication,
desktop readiness, signing or notarization is implied by this evidence.
