# HAR-HU-56 — Delivery bound to the contract and verified bytes

Status: in progress. HU55 dependency available locally and in review.
First OCI application; no equivalent isolation is attributed to the none backend.

## Import scope

Acceptance authority lives in a private host context during the run,
inherited by child runs. The contract is not taken from tool
arguments. The importer checks the freshly recalculated patch inside the host
mutation lock, before any write or quarantine. It rejects the
entire patch if a path falls outside allowedWritePaths, intersects a protected
file or points to another workspace. The entry set covers creation,
update, deletion and both ends of moves.

Ordinary approval does not remove this restriction. Integrated test with
runHarness, simulated model and simulated OCI adapter: verify_and_apply_reviewed_edits
approved for outside.txt fails at import, leaves the host unchanged and persists
TASK_ACCEPTANCE_SCOPE_VIOLATION diagnostics in additive acceptance evidence.
No model prose can transform that diagnostic into acceptance.

The diagnostic preserves run/patch/paths and is bound to the contract
digest/revision. It reappears when resuming the same contract; a new revision does not inherit
evidence from the previous one. Resume takes evidence only from durable state, removing
caller-supplied values if missing from the store. Stable statuses are preserved.

## Receipts and all-checks gate

The host records per check: contract digest/revision, run, OCI identity,
patchId, snapshotDigest, exact argv digest, exitCode, timeout and byte stability
before/after. Collection bounded by the contract's 32 checks.
A new attempt invalidates the previous in-memory receipt before executing.
Receipt snapshots are saved through run checkpoints and
recovered only if matching the same contract/revision and argv.

The importer now requires all successful receipts over the exact bytes
recalculated inside the lock. Additional snapshot identity includes hidden/ignored
files and modes, with byte/entry limits and link rejection.
Thus, changing .env after verification prevents import even if the exportable
patchId is unchanged. This identity exposes no content and does not certify the none backend.

runCommand observes only commands matching declared checks.
Package scripts revalidate manifest/script/argv within the snapshot,
even when invoked as raw argv. Under a contract, batches execute the
already approved argv sequentially to produce individual results; no
commands are added. Checks execute through existing approvals.

### Reconcile recovered checks with the journal

New receipts include the provider call identifier and tool name observed by the host. On resume, the collector requires a unique completed journal entry from the same run, exact argv and result, with available execution times. It does not reuse old receipts without provenance, aggregated batch results or ambiguous evidence. A pending/running attempt, or a later or overlapping attempt of the same check, invalidates reuse. This executes no commands or uncertain effects again: it leaves the requirement pending for the existing authorized flow.

Host-observed start time was added to the private receipt; reconciliation requires durable completion after that start and continues rejecting uncertain, overlapping or later attempts. Local regression covers a completed row without `startedAt` and inconsistent times.

- Journaled import with an earlier run checkpoint: does not repeat import and preserves incomplete acceptance. Durable injection reproduces the gap between both writes; this is not a physical Docker crash test.
