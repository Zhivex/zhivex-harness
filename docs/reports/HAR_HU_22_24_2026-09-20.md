## Acceptance evidence

- HU-22: strict shared commands dispatched through an owner-private Unix socket; 0700 directory, 0600 socket/credentials/ownership file, bearer authentication, rejected browser origins and no TCP listener. Node launcher supports graceful drain and explicit dead-owner recovery. Disconnecting the client leaves admitted execution and state with the runtime owner.
- HU-23: SQLite event IDs and ordered cursors bound to session/run and scope; transactional snapshots, count/time retention, split-token redaction and bounded text. Expired cursors explicitly return a replacement snapshot and recovery cursor. Reconnecting readers do not execute tools.
- HU-24: shared admission and expected revisions permit one approval winner; competing decisions conflict. Full approval digests, scope, persisted checkpoint expiry and engine workspace/signature checks remain enforced. Active cancellation persists the request before aborting the owner. Node crash-at-approval recovery preserves state, replay and one completed tool journal receipt.

## Operational limits and remaining goal scope

The launcher must use a canonical service directory for the workspace/scope. It never steals a live PID lock and does not automatically replay uncertain effects. Client-command idempotency is connection-epoch scoped; a process restart invalidates old tokens and epochs and requires querying durable state before new decisions. Activity snapshots are bounded, text is redacted before persistence, and an unflushed partial token may be omitted on abrupt crash.

CLI service mode (HU-25), Electron/React and product flows (HU-26–33), installer signing/notarization (HU-34) and update recovery (HU-35) remain in the active objective. The user requested preparing packaging now and configuring signing later; unsigned artifacts must not close the signed/notarized acceptance criterion. No push, publication or release recommendation is made by this increment.
