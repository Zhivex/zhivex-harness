# HU35: authenticated update download foundation

Implemented host-side primitives in `desktop/src/update-manifest.ts` and
`desktop/src/update-download.ts`. They are not wired into main, IPC, or UI yet.
There is no production update feed/key configured and no automatic installation.

The envelope signs the exact JSON payload bytes using Ed25519. The verifying
public key is supplied by trusted host/build configuration, never by the envelope.
Strict schema and size limits reject unknown fields, wrong products/platforms,
invalid signatures, noncanonical encoding, stale manifests, incompatible declared
state ranges, downgrades and same-version replays. SemVer comparison treats
numeric prerelease components numerically and ignores build metadata. Stable and
prerelease channels are explicit and must match the signed version classification.
Manifest validity is bounded to seven days, with five minutes of publisher clock
skew. These are initial policy defaults, not a remotely configurable trust policy.

Only authenticated, frozen objects from the verifier enter download staging.
The first URL is restricted to the Harness repository's HTTPS GitHub release DMG
namespace. Redirects are manual, capped at three, and restricted to explicit
GitHub asset hosts without credentials or custom ports. Downloads enforce signed
size (maximum 1 GiB) and SHA-256 while streaming; reject content encodings and
inconsistent lengths; use exclusive 0600 partial files in private 0700 directories;
and rename only after successful hash/size verification and fsync. Failure or
abort removes that download's directory. Fixed error codes omit network responses,
URLs and filesystem paths. A cleanup failure is distinguished explicitly.
The caller must provide a trusted host-controlled staging root, not a workspace
or renderer-selected path. Completed artifacts still require revalidation before
use, native signature checks, and installation coordination.

## Verification

`bun test desktop/tests/update.test.ts`: **10 pass, 0 fail, 105 assertions**.
`bun run --cwd desktop typecheck`: passed.

Tests use ephemeral signing keys and synthetic bytes, with no production key,
network request, valid installer, or actual app replacement. They cover valid
streaming through an allowed redirect; signature/key/algorithm/field tampering;
version/channel/state/expiry rejection; short, oversized, corrupt and interrupted
downloads; invalid headers; hostile redirects and loops; stalled body/fetch
deadlines; caller cancellation; directory symlinks and private file permissions.

## Outstanding acceptance

All HU35 acceptance boxes remain open. The manifest signature does not prove a
macOS Developer ID signature or notarization. Remaining work includes trusted
build/feed configuration, native publisher verification, user-facing update
flow, admission control for active/critical work, installation failure recovery,
state backup/migration and refusal of incompatible schemas by an older app.
Existing core backup/recovery facilities should be reused for state handling.
No new installer was generated by this increment; the unsigned HU34 DMG remains
the previous artifact. No push or publication.
