## Bounded correction in the same child

`maxCorrections` now implements zero to two attempts. Middleware transforms only an invalid final response into an internal feedback step without file effects. The model still sees only `read_file`; directly invoking the hidden control is rejected. The invalid candidate remains tool-call data to preserve evidence without concatenating it into final JSON. Feedback and the next generation go through the normal SDK: they consume tool calls, steps and tokens, remain in the same run and parent-child binding, and preserve existing journal and cancellation. Exhausting a budget may prevent correction before the configured maximum.

Final guardrails check the result against real receipts and reject excess attempts. The parent's durable evaluation also preserves `correctionsUsed`. Only this internal effect-free control was enabled in the OCI tool allowlist; no filesystem, shell or command permissions were added.
