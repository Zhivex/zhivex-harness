# Minimum offline evaluation preparation

This cohort prepares the approved next-version minimum's evaluation protocol. It contains **12 frozen synthetic JS/TS tasks across three repository templates** (four tasks each), and **two separate development tasks**. They are deterministic scaffolding, not real privately sourced holdout tasks. Scripted model results establish fixture validity and runtime behavior, never model quality or competitive performance. The later 12 × 3 × 2 paid campaign requires separate budget approval and real-task selection.

The frozen private catalog and reference/hidden acceptance bytes are a local-only deliverable outside this public Git checkout, at `../reference/private-minimum-evals/` (directory mode 0700, files mode 0600). Their SHA-256 is `e0b1f95bb96031a4d72907a8243c23529a1ef27332532e435f9681c5b004ca4e`. They must never be committed, pushed or included in npm artifacts. The runner has no private default: provide `--fixtures=<private-directory>` or `ZHIVEX_MINIMUM_EVAL_FIXTURES` explicitly. The checked SHA-256 freezes the complete cohort, including instructions, original files, reference solutions, oracle, constraints and rubric. Changes require a new revision and digest before execution. Do not tune prompts or thresholds against holdout outcomes. Use the separate development split for runner changes.

Public CI tests are self-contained. `scripts/minimum-evals/public-regression-fixtures.ts` contains only the two public development examples (whitespace normalization and numeric clamping); it generates twelve duplicate contract rows plus the two development rows in a temporary directory. These generated rows exercise schema, isolation, verification and restart contracts; they are not the twelve private holdout tasks. CI never reads the local private cohort.

Each private task materializes only its starter implementation, documentation, visible public check, package manifest and exact native `/task` acceptance contract. The oracle and reference solution never enter the task workspace or prompt. The offline script itself intentionally gives its synthetic model the reference patch; this is a regression double, not a withheld model exam. Production model evaluation must keep these verifier files outside every enabled filesystem/tool boundary. Local host execution here is not an adversarial process sandbox.

After closing the task session, the grader reads bounded regular files, rejects symlinks/hardlinks and extra or protected-file changes, and applies only allowlisted implementation changes to a clean copy. It runs the original visible check and the hidden oracle there, ignoring submitted check edits. The frozen public and hidden checks both fail for an empty patch and both pass for the reference. One task changes two files; the long-context task has archived notes and a separate authoritative contract; the continuation task closes/reopens at a durable approval before continuing the same run.

Run the public regression tests with `bun test tests/minimum-offline-evals.test.ts`. Run a local private cohort with Bun 1.4.0, serially, without credentials or provider calls:

```sh
export ZHIVEX_MINIMUM_EVAL_FIXTURES="/private/path/to/private-minimum-evals"
bun scripts/minimum-task-evals.ts --validate
bun scripts/minimum-task-evals.ts --validate --split=development
bun scripts/minimum-task-evals.ts --plan --report=/tmp/minimum-unexecuted-plan.json
NODE_PATH="$PWD/node_modules" bun scripts/minimum-task-evals.ts --variant=candidate --report=/tmp/minimum-candidate.json
NODE_PATH="$PWD/node_modules" bun scripts/minimum-task-evals.ts --variant=rc6 --engine=/path/to/rc6/src/engine/index.ts --report=/tmp/minimum-rc6.json
bun scripts/minimum-task-evals.ts --mode=empty --report=/tmp/minimum-empty.json
```

Run RC6 and candidate with the same frozen cohort, machine, runtime, resource settings, scripted events and task ceiling. Reports include engine commit, module/diff digests, source dependency lock digest, explicit dependency-resolution mode, OS/CPU/runtime identity, cache qualifications and every attempt. When RC6 lacks installed dependencies, Bun can use `NODE_PATH` to the same installed dependency tree for both variants without editing either source checkout; verify both lock files are identical first. One task runs with one owner through approval resumes; fresh-run/revise scenarios where RC6 cannot enforce the same cumulative task ceiling belong to separate functional evidence, not cost A/B. The runner is offline-only and offers no live-provider execution switch.

Reports and durable per-attempt JSONL journals are created with mode 0600 and exclusive creation; no previous evidence is overwritten. Reports contain submitted patches and must stay private, outside npm artifacts and model context. Infrastructure failures and empty-patch failures remain recorded. Do not publish reference or hidden checks as benchmark tasks. The prepared seeded matrix has 72 **not-executed** entries, blocked by task with alternating variants and three fresh repetitions; retries are disabled. It records prerequisites rather than inventing a provider, pricing or approval.

Each attempt records `runCompleted`, `oraclePassed`, `scopePassed`, `protectedFilesUnchanged`, `publicCheckPassed`, `automatedPass`, failure class, usage completeness, calls, compactions, tool count, patch bytes, wall/active time, fixed model settings and budget. Unknown provider cost, repeated work, actual human minutes and interventions stay null. `acceptedChange` stays null until independent human review. Synthetic usage is explicitly not billing. Human review must be blinded to variant using a separate review projection and assess correctness, exact scope, readability and unnecessary complexity against the frozen rubric; do not send the experiment manifest to that reviewer.

Before a paid campaign, freeze immutable model/endpoint (or record its observation window), reasoning, temperature, effective caps, tools, policies, resources, known cache state and budget approval. Validate reference/empty checks again. Freeze decision thresholds after repeating RC6 and before looking at holdout outcomes. Report initial success separately from eventual success; retain all planned failures, retries and paid verifier cost. Cost per accepted result is total planned spend divided by accepted results, undefined with zero accepts, and incomplete whenever spend is unknown. Compare whole-campaign latency and latency in pairs where both pass. Twelve tasks do not support broad generalization or a stable p95 claim.
