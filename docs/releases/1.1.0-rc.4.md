# 1.1.0-rc.4 candidate readiness

Prepared on 2026-09-22. RC.4 is unpublished and targets npm `next`.
The registry currently serves RC.3 on `next` and 1.0.0 on `latest`;
RC.3's immutable version and tag must not be reused.

## Scope since RC.3

- Pin the latest stable SDK/provider versions verified against npm on 2026-09-22:
  Agents `1.8.0`, Core `1.22.0`, Gemini `0.12.1`, Meta `0.2.6`, OpenAI `0.13.4`
  and Qwen `0.15.0`, with the shared Core override retained.
- Restore the TypeScript `6.0.3` compiler API alias used by architecture and
  Stable signature checks; the build compiler remains TypeScript `7.0.2`.
- Adapt compaction retention to estimated tokens and remaining input allowance,
  preserve working plans, and support explicit unlimited cumulative token budgets
  while retaining non-token execution controls.
- CLI help works when appended to a task or options, groups related options,
  provides examples and supports `--name=value` for value options.
- Explicit UTF-8 stdin tasks through `zhx run -` and `zhx review -`, capped at
  1 MiB, preserve multiline text and the existing approval requirements.
- Atomic personal profile updates through `zhx init --update`, provider/model
  selection after declining the default profile, and actionable error recovery.
- Shared CLI/Desktop model catalog with primary/other choices, lifecycle and
  validation metadata, custom IDs, and optional HTTPS refresh with cached fallback.
  Catalog entries do not imply new provider certification.
- Desktop alpha improvements to Markdown, diffs, navigation, local preferences,
  accessibility and external-link handling. Desktop keeps its independent private
  `0.1.0-alpha.1` version; this does not establish signing, notarization or production
  auto-update readiness.

## Release identity and evidence

`package.json` is the runtime version source. The representative assembly matrix
authorizes `v1.1.0-rc.4` with the existing explicit model pins: Meta
`muse-spark-1.2`, Qwen `qwen3.8-max`, and OpenAI `gpt-5.6-luna`.
Historical RC.3 and 1.0 matrix entries are retained.

`release-status.json` remains the separately verified stable 1.0.0 publication
record. It is not evidence of RC.4 publication or certification. The changes above
are the current working-tree candidate scope; the final release must bind the
reviewed commit and exact tarball. Local checks do not certify that artifact.

## Remaining publication gates

1. Validate and review the complete candidate, including current CLI, catalog and
   Desktop changes; integrate into main and pass CI and CodeQL on that exact commit.
2. Run `bun run release:prepare --sha <full-main-sha>` from a clean checkout.
   This is a read-only preflight, including registry absence and release identity.
3. Use the protected publication path to create the new annotated `v1.1.0-rc.4`
   tag and dispatch the release workflow for channel `next`.
4. Pass exact-tarball, live-provider and representative gates; verify registry
   integrity, provenance and the `next` dist-tag before reporting publication.
