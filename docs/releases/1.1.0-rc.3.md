# 1.1.0-rc.3 candidate readiness

Prepared on 2026-09-22. Targets npm `next`; RC.3 publication and release-bound
certification remain pending. Stable `latest` remains 1.0.0. RC.2 is already
published on `next`; its immutable version and tag must not be reused.

## Scope

- Compact console activity: one bounded live line, summaries between messages,
  explicit failures/checks/approvals, and `/verbose` for individual events.
- Safe failure diagnostics distinguish known budget and step limits from unknown
  run failures without printing arbitrary provider payloads.
- Qwen cumulative token enforcement for runs without subagents, including approval
  resume, without injecting `maxTokens`. A single response may cross the budget;
  its tools and subsequent calls are stopped. This is not an exact pre-request
  input-token ceiling or a new guarantee for delegated runs.
- Responsibility-based module layout, explicit Desktop integration surfaces and
  architecture checks. Public API contracts and persistence formats are preserved.
- Release preflight, reviewed-main preparation, retained tarballs and recovery
  summaries from PR #93.

The existing Desktop remains a separate private alpha preview; this candidate
makes no new signing, notarization or production auto-update claim.

## Evidence boundary

Before the version bump, the integrated source passed 892 tests with one skipped,
plus architecture, documentation, contract, type, build, migration and release
metadata checks. Targeted Qwen tests cover cumulative input/output limits,
approval resume and preventing tools from an over-budget response. Terminal
regressions cover grouped activity and visible failures/checks/approvals.

These are local checks, not certification of the RC.3 npm artifact. RC.3 must
receive its own remote CI, CodeQL, exact-package, live-provider and representative
certification. Historical 1.0 and RC.2 evidence is not RC.3 evidence.

## RC.3 local preparation

Candidate validation passed 892 tests (one platform-specific skip), architecture,
documentation, contracts, both type checks, migrations, evaluations, workspace and
safe-fix benchmarks, MCP interoperability and OCI execution smoke. The installed
RC.3 package smoke passed after making the conversation fixture select OpenAI
explicitly instead of waiting for first-use setup; onboarding remains independently
covered. The package was rebuilt and retested after that fixture correction.
Dependency audit reported no vulnerabilities across 48 packages and zero untrusted
lifecycle scripts. Release metadata preflight passed for the exact RC.3 model pins.

## Remaining publication gates

1. Validate the candidate metadata and source through the protected PR process.
2. Integrate into main and pass CI and CodeQL for that exact commit.
3. Run `release:prepare --sha <full-main-sha>` on a clean main checkout; it checks
   registry absence and release identity without publishing.
4. Use the protected preparation/publication path to create a new annotated
   `v1.1.0-rc.3` tag and dispatch `release.yml` on that exact tag, channel `next`.
5. Pass exact-tarball validation, live-provider and representative gates, then
   verify npm integrity, provenance and the `next` dist-tag before reporting release.
