# 1.1.0-rc.7 candidate readiness

Prepared on 2026-09-22. RC7 is unpublished and targets npm `next`.
It supersedes the tagged but unpublished RC6 without moving historical tags.

## OpenAI model migration

- New CLI/Desktop OpenAI choices use `gpt-6-luna`; saved explicit model choices remain unchanged.
- The RC7 assembly row and representative workflow pin `gpt-6-luna`. Existing release mappings retain their original models.
- Qwen remains `qwen3.8-flash`; Meta remains `muse-spark-1.2`.
- OpenAI tool certification uses Responses API, consistent with the [official model documentation](https://developers.openai.com/api/docs/models/gpt-6-luna).

[RC6 run 35804362922](https://github.com/Zhivex/zhivex-harness/actions/runs/35804362922)
passed exact-artifact validation. Meta and Qwen passed the base live gate;

## Validation boundary

Local model tests and live checks must be distinguished from protected
release-bound certification. After integration and CI on the exact main SHA,
a new tarball must pass all required gates before publication to `next`.

## Local live checks

On 2026-09-22 (Argentina local date), GPT-6 Luna passed the base
approval/restart/exactly-once smoke, bounded reviewer orchestration, model-directed
OCI execution, and the OpenAI-parent/Qwen-reviewer route in the working checkout.
The first base attempt failed with an unclassified execution error; a second
attempt passed. This is not evidence of deterministic reliability or a fix for
the original RC6 failure. Base-smoke errors now retain an allowlisted checkpoint
and assertion error kind without exposing actual/expected values or raw responses.
