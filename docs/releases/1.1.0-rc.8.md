# 1.1.0-rc.8 candidate readiness

Prepared on 2026-09-22. RC8 targets npm `next`, superseding the tagged but
unpublished RC7 without moving historical tags.

## Root cause and mitigation

OpenAI adapter 0.13.4 serializes raw results named `apply_patch` as native
`apply_patch_call_output`, even when the original call is a function. Harness's
`patch-result` object has no native `output` property, so its receipt is dropped.
A captured local request confirmed that the approved write had executed exactly
once while OpenAI received no receipt. The model sometimes inferred success and
sometimes reported that approval was still pending. A passing retry did not
prove a sound transport.

Harness now requests `toolResultFormat: envelope` at the built-in OpenAI model
boundary for generation and streaming. Function output and error payloads survive;
explicit native tool metadata remains authoritative. No SDK files are patched,
and the smoke still requires its completion marker, exact file content, one
approved execution, persisted restart, and one completed journal entry.

The upstream repair and publication requirements are tracked in the
[SDK user story](https://app.notion.com/p/3e4777b104f68141bc49cae78822780c).
The SDK defect is not considered fixed by this consumer mitigation.

## Evidence and release boundary

[RC7 run](https://github.com/Zhivex/zhivex-harness/actions/runs/35806499955)
failed `resume_output`; later gates and publication were skipped. The local
instrumented reproduction confirmed the missing receipt; the mitigated run
sent `function_call_output` with the receipt and passed completion, exact effect,
and journal checks. Diagnostics retained types, flags and counts, not raw payloads.

Eighteen offline tests exercise the published adapter's generation and streaming
transport with successful/error results for `apply_patch`, `shell`, `computer`,
and ordinary functions, plus explicit native-tool controls.

Release certification must run against the new immutable tarball after merge.
Local results are not a substitute. Model pins remain Meta `muse-spark-1.2`,
Qwen `qwen3.8-flash`, and OpenAI `gpt-6-luna`.

Local `bun run check` passed: 961 tests passed, one skipped, zero failed;
architecture, docs, type checks, migration/evaluation gates, OCI/MCP and installed
package smokes passed. The official OpenAI base smoke also passed with process
restart, one approved write and one completed journal entry. Full multi-provider
certification remains the protected release gate.

## Protected release result

[Run 35808383244](https://github.com/Zhivex/zhivex-harness/actions/runs/35808383244)
passed exact-artifact validation and the complete base provider gate in both
attempts. Both attempts stopped at Qwen orchestration after Meta passed;
OpenAI orchestration, subsequent gates, representative evaluation and publication
were skipped. RC8 remains unpublished.

A separate local Qwen reproduction returned `GuardrailTriggeredError`: the
reviewer required three tool calls with a limit of one. The parent had delegated
a different prompt from the requested fixture. Another local execution preserved
the requested delegation and passed. This establishes local task drift and
correct budget enforcement, not the exact cause of the cloud failures: those
older diagnostics did not retain the guardrail kind or counters. New diagnostics
allowlist that kind and bounded budget counters while discarding all arbitrary
metadata. Do not weaken budgets or treat a passing retry as proof of reliability.
