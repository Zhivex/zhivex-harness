# 1.1.0-rc.1 candidate readiness

Prepared on 2026-09-21. Source candidate only; not published or certified.

## Scope

Compatible minor release after 1.0.0: console navigation, safe paste and streaming,
command help, onboarding, usage accounting, authenticated local service and replay.
Desktop remains a separately versioned private 0.1.0-alpha.1 preview.

## Validation

Local preparation: **GO for review and remote certification; NO-GO for publication
until the gates below pass**. This report describes local validation of the
candidate on `feat/harness-desktop`, not remote CI or published-artifact evidence.

The final review corrections bind the default-profile confirmation to the displayed
provider/model and explicitly install pinned Electron before native tests in both
macOS CI jobs. Other dependency lifecycle scripts remain disabled. Desktop uses
`@electron/packager@20.3.0` with its named export and has its own dependency audit
and Dependabot coverage. CI also runs the offline console PTY regressions.

## Publication gates

1. Review and integrate the complete candidate into main with passing CI.
2. Replace the candidate changelog Unreleased date with the actual release date.
3. Run the full release gate from a clean checkout and verify the version is absent from npm.
4. Create an annotated v1.1.0-rc.1 tag at the reviewed source commit.
5. Run the protected release workflow on channel next, including fresh OCI, live-provider, representative-matrix and exact-artifact checks.
6. Verify installed artifact, registry integrity and SLSA provenance before recording publication.

Keep release-status.json as the published 1.0.0 record until a new verified stable
release replaces it. Do not reuse its certification for this source candidate.

Desktop production distribution separately requires Developer ID signing,
notarization, publisher/feed configuration and a real signed update/rollback test.
Automatic updates remain disabled. Gemini remains provisional. The existing
6/10 daily-workflow pilot remains HOLD; this candidate makes no improved coding
accuracy claim.
